# MoveX GO — состояние проекта и сетап на новом ПК

Документ на 17 ноября 2026. Подробные правила и «почему так» — в
`CLAUDE.md` в корне репозитория: там записано всё, на чём уже
спотыкались. Этот файл — короткая выжимка: что готово, что нет и как
поднять проект на другом компьютере.

---

## 1. Что это

Платформа аренды строительной техники (Узбекистан). Клиент заказывает
технику «как такси», владелец её сдаёт.

| Часть | Папка | Технологии |
|---|---|---|
| API | `backend/` | Python 3.12, FastAPI, PostgreSQL 16, Alembic |
| Админка | `admin/` | чистый PHP + PDO, ходит в ту же базу напрямую |
| Приложение | `mobile/` | Flutter (Dart `^3.8.1`), iOS + Android |

- Репозиторий: `github.com/oybeff/movex` (приватный), ветка `main`.
- Прод: `https://movexgo.uz`, админка `https://movexgo.uz/panel/`.
- Макет: Figma, файлы в команде «BRB Mobile app» — Design System,
  «Mijoz ilovasi» (клиент), «Texnika egasi» (владелец).

## 2. Состояние на 17.11.2026

### Готово

**Клиентское приложение по новому макету (синий + жёлтый).** Все кадры
страницы «01 Asosiy — Xarita va Katalog» сделаны:

- вход: заставка, онбординг, телефон, SMS-код, имя, ПИН;
- заказ «как такси», шаги 1–10: откуда/куда, тип техники, тариф
  (Ekonom / Tezkor / Kun davomida), навесное, время, поиск, «в пути»,
  работа, завершение, оплата и оценка;
- состояния заказа B1–B7: отмена владельцем, опоздание, продление,
  автоподтверждение, жалоба, пусто, загрузка;
- «Мои заказы», детали заказа, чат с владельцем, уведомления, помощь
  (M1–M6);
- профиль Pr1–Pr6: личные данные с фото, способы оплаты, сохранённые
  адреса, язык, выход;
- оплата картой (K1–K6, T4–T7, E7): привязка через Multicard, холд и
  списание;
- исключения E1–E6, U1–U7: нет геолокации, нет сети, вне зоны, не нашли
  технику, сессия истекла, обязательное обновление, техработы, удаление
  аккаунта.

**Сервер под всё это:** тарифы и навесное (задаёт админ), наличные с
комиссией с баланса владельца, ход заказа (выехал / начал / закончил /
продление / опоздание), жалобы, карты, профиль, зона обслуживания.

**Админка:** тарифы (`tariffs.php`), жалобы (`problems.php`), наличные и
бонус пользователю, настройки приложения («Ilova holati»).

**Приложение владельца:** кнопки по заказу — принять, отказать, выехал,
начал, закончил, опоздание, согласие на продление.

**Проверки:** `bash backend/tests/run_all.sh` — все наборы зелёные;
`flutter analyze` — 0 ошибок; web-сборка проходит.

### Не готово / не проверено

1. **На реальном телефоне не проверено ничего.** Всё смотрелось в
   браузере. В браузере не работают карта Яндекса, поиск адреса и форма
   привязки карты (WebView) — их вживую не видел никто. Первый шаг
   перед сдачей — собрать APK и пройти заказ на Android.
2. **В браузере не открывались** кадры E2, E7, K4/K6, T4/T6, U1–U5, U7,
   B7 (код есть, глазами с макетом не сверены).
3. **K2, K3, K5, T1–T3 один в один не сделать.** Ввод номера карты и
   SMS-кода — страница Multicard, а не наша: свои поля карты требуют
   сертификата PCI DSS.
4. **Ждут решения владельца:**
   - шаг 8: до выезда владельца заголовок «Texnika topildi», в макете
     «Texnika yo'lda»;
   - «Balans» в способах оплаты (в макете только «Naqd pul»);
   - в профиле старые разделы «Katalog», «E'lonlar», «Texnika xaritada»
     (в макете их нет).
5. **Известные недоделки:** настоящего чека в M3 нет (шторка);
   push-уведомления не уходят — нет проекта Firebase; в выборе языка нет
   узбекской кириллицы; по макету приложений два (клиент и владелец), а
   сейчас одно, и в нём остался экран выбора роли.
   Два уведомления молча не создаются: типов `listing_offer` и
   `material_moderated` нет в CHECK `check_notification_type` (нужна
   миграция, ошибка видна только в логе сервера).
6. **Приложение владельца по новому макету не переделано** — только
   добавлены кнопки по заказу.
7. **На прод не выкачено.** Новые миграции (тарифы, наличные, карты,
   жалобы, профиль, удаление диагностики) на сервере не накатывались.
   Порядок выката — `docs/RELEASE.md`.
8. **Боевых ключей Rahmat (Multicard) нет**, платежи работают на
   песочнице. Подробно — `docs/backend/PAYMENTS.md`.

## 3. Сетап на новом ПК

### 3.1 Что перенести с этого Мака руками (в git этого нет и не будет)

| Что | Где лежит | Зачем |
|---|---|---|
| `backend/.env` | в репозитории, игнорируется | все ключи и доступ к базе |
| дамп базы | сделать: `bash backend/scripts/backup.sh` | живые данные для разработки |
| `mobile/android/app/upload-keystore.jks` и `mobile/android/key.properties` | в репозитории, игнорируются | подпись релиза для Google Play. **Потеряете — обновить приложение в Play будет нельзя** |
| `~/.ssh/movex_deploy` и `movex_deploy.pub` | домашняя папка | вход на прод-сервер |

Передавать флешкой или менеджером паролей — не почтой и не мессенджером
открытым текстом.

### 3.2 Поставить

**macOS:**

```bash
brew install python@3.12 postgresql@16 php git gh
brew install --cask flutter            # или по инструкции flutter.dev
brew services start postgresql@16
```

**Windows:** Python 3.12 (python.org, галочка «Add to PATH»),
PostgreSQL 16 (postgresql.org, установщик EDB), PHP 8 (windows.php.net,
нужны расширения `pdo_pgsql` и `curl` в `php.ini`), Git, GitHub CLI,
Flutter (flutter.dev → Windows). Команды ниже — для macOS/Linux; на
Windows вместо `source venv/bin/activate` пишется
`venv\Scripts\activate`.

Для сборки Android дополнительно: Android Studio (SDK) и JDK 17 или 21.

### 3.3 Код

```bash
gh auth login                       # аккаунт oybeff, HTTPS
gh repo clone oybeff/movex
cd movex
```

Положить `backend/.env` (из 3.1).

### 3.4 База

```bash
createdb movex_go
```

Дальше один из двух путей:

- **с данными (рекомендую):** `bash backend/scripts/restore.sh <файл_дампа>`
- **пустая:** из `backend/` — `python scripts/init_db.py`, затем
  `make migrate`, затем `python scripts/create_admin.py`

В `backend/.env` строка `DATABASE_URL` должна указывать на эту базу.

### 3.5 Бэкенд

```bash
cd backend
python3.12 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
make migrate                        # alembic upgrade head
make run                            # http://localhost:8000, Swagger — /docs
```

Проверка: `curl http://localhost:8000/health` → `"status":"healthy"`.

Все автотесты (сервер должен быть запущен):

```bash
bash tests/run_all.sh
# если сервер на другом порту:
API=http://127.0.0.1:8010 bash tests/run_all.sh
```

Для локальной разработки в `.env` удобно `OTP_TEST_MODE=true`: код из SMS
приходит прямо в ответе API, SMS не тратятся.

### 3.6 Админка

```bash
cd admin
php -S localhost:8080
```

Открыть `http://localhost:8080/login.php`. Доступ к базе админка берёт
из `backend/.env`.

### 3.7 Приложение

```bash
cd mobile
flutter pub get
flutter analyze                     # должно быть 0 ошибок
```

**Адрес сервера обязателен** — без него приложение пойдёт на прод:

```bash
# в браузере (карта там не работает — это нормально)
flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:8000

# на Android-телефоне в той же Wi-Fi сети (IP компьютера)
flutter run --dart-define=API_BASE_URL=http://192.168.1.XX:8000

# релизный APK на прод
flutter build apk --release --dart-define=API_BASE_URL=https://movexgo.uz
```

Для телефона по HTTP IP компьютера должен быть вписан в
`android/app/src/main/res/xml/network_security_config.xml` — точно, без
масок. Подробно — `docs/TESTING_ON_PHONE.md`.

**iPhone** собирается только на Маке с полным Xcode; шесть препятствий,
которые уже пройдены (платформа iOS, минимальная версия 15.0, iCloud на
Рабочем столе и т.д.), описаны в `CLAUDE.md`, раздел «Сборка под
iPhone».

### 3.8 Выкат на прод

Чистый сервер — комплект `deploy/` (`deploy/README.md`). Обновление уже
работающего — `docs/RELEASE.md`. Сервер: `189.74.98.45`, вход по ключу
`movex_deploy`, код в `/opt/movex`, служба `movex-api`.
