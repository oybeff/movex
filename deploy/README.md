# Выкат MoveX GO на новый сервер

Всё, что нужно для переезда на купленный VPS. Порядок важен: домен
прописывается первым, потому что без него не выпустить сертификат, а без
сертификата не включить вебхук Telegram.

Ресурсов хватает: FastAPI в двух воркерах, PostgreSQL и PHP-админка на
2 ГБ живут спокойно, скрипт настройки добавляет 2 ГБ подкачки и
поджимает postgres под этот объём.

## Шаг 1. Домен — одна запись у регистратора

Сейчас поднимаемся на **`movex.004.uz`** — он уже зашит в собранный
`.aab`, поэтому приложение пересобирать не нужно. Домен зарегистрирован
не в Eskiz, запись меняется в панели того провайдера, где он куплен.

| Имя | Тип | Было | Стало | TTL |
|---|---|---|---|---|
| `movex` (в зоне `004.uz`) | A | `159.69.38.202` | `189.74.98.45` | 300 |

**Существующую запись именно ПРАВИТЬ, а не добавлять вторую.** Две
A-записи на одно имя — это не «запасной сервер», а случайный выбор:
часть людей уедет на старый адрес и увидит мёртвое приложение.

Больше ничего в DNS не нужно. Админка живёт на том же домене, по пути
**`/panel/`**, а не на `admin.movex.004.uz`: это домен четвёртого уровня,
и не всякий регистратор даёт такую запись. На `/admin` её положить
нельзя — этот путь у API занят своим роутером.

Проверить, что разошлось (обычно 5–30 минут, изредка до 2 часов):

```bash
dig +short movex.004.uz          # должно стать 189.74.98.45
```

### Когда появится новый домен

Тогда его добавляют **рядом**, а не вместо:

```bash
ADMIN_MODE=path DOMAIN=новый.домен bash /opt/movex/deploy/bootstrap_ubuntu24.sh
DOMAIN=новый.домен bash /opt/movex/deploy/enable_tls.sh
```

`movex.004.uz` при этом должен продолжать работать. Причина простая: у
людей, поставивших приложение из Плей Маркета, адрес зашит внутри и
меняется только с обновлением. Выключите старый домен — у всех, кто не
обновился, приложение перестанет открываться.

## Шаг 3. Код на сервер

Каталоги `backend/` и `admin/` должны лежать **рядом**: `admin/config.php`
читает доступ к базе из `../backend/.env`. Разложить их порознь —
значит уронить админку.

```bash
ssh root@189.74.98.45
mkdir -p /opt/movex
# либо git clone <репозиторий> /opt/movex
# либо с локальной машины:
#   rsync -az --exclude venv --exclude .env --exclude media \
#         ~/Desktop/outsource/movex/ root@189.74.98.45:/opt/movex/
```

`.env`, `venv/` и `media/` не копируются: первый создаётся на сервере со
своими ключами, второй собирается под тамошний Python, третий — данные.

## Шаг 4. Настройка сервера — одна команда

```bash
DOMAIN=movex.004.uz bash /opt/movex/deploy/bootstrap_ubuntu24.sh
```

Админка по умолчанию встаёт на `/panel/`. Если у регистратора всё-таки
можно завести `admin.movex.004.uz` и так удобнее — `ADMIN_MODE=subdomain`,
но тогда нужна и вторая A-запись.

Ставит и связывает: пакеты, подкачку, пользователя `movex`, PostgreSQL с
базой и паролем, `.env` со сгенерированными ключами, venv, схему базы,
systemd-службу, nginx для API и админки, php-fpm, файрвол, ночные дампы.

Скрипт идемпотентный: повторный запуск ничего не ломает и **не
перезаписывает `.env`**.

> Старые `backend/scripts/quick_deploy.sh` и `deploy_movex_004_uz.sh` не
> использовать. Они ставят `python3.11` и Apache, а в Ubuntu 24.04 пакета
> `python3.11` нет вообще — падают на первом `apt install`. Админку они
> не поднимают совсем.

## Шаг 5. Сертификаты

Только когда `dig` из шага 1 отдаёт правильный адрес:

```bash
DOMAIN=movex.004.uz EMAIL=вы@почта bash /opt/movex/deploy/enable_tls.sh
```

Скрипт сам сверяет, куда указывает домен, и не пойдёт в Let's Encrypt
раньше времени: после пяти неудачных попыток подряд домен блокируется
на час.

## Шаг 6. Ключи в `.env`

`/opt/movex/backend/.env`, после правки `systemctl restart movex-api`.

```bash
TELEGRAM_BOT_TOKEN=          # токен бота
TELEGRAM_BOT_USERNAME=       # логин бота без @
ESKIZ_EMAIL=                 # SMS — запасной путь, если Telegram не дошёл
ESKIZ_PASSWORD=
```

`DATABASE_URL`, `SECRET_KEY` и `TELEGRAM_WEBHOOK_SECRET` скрипт уже
сгенерировал — их не трогать.

Click, Payme и FCM остаются пустыми: боевых ключей пока нет
(`docs/backend/PAYMENTS.md`, `docs/backend/NOTIFICATIONS.md`). Приложение
с пустыми ключами работает, просто эти способы оплаты и push молчат.

## Шаг 7. Вебхук Telegram

```bash
cd /opt/movex/backend
venv/bin/python scripts/telegram_webhook.py set https://movex.004.uz
venv/bin/python scripts/telegram_webhook.py info     # проверить
```

**Почему в проде именно вебхук.** Опрос (`TELEGRAM_POLLING=true`)
запускается в каждом процессе uvicorn, а их два. Два опроса одного бота
Telegram встречает ответом 409, и вход в приложение начинает работать
через раз. Вебхук от числа процессов не зависит: сообщение приходит
одно, обрабатывает его тот процесс, которому оно досталось.

Адрес закрыт секретным словом из `.env`. Пустое слово — адрес отдаёт 404:
иначе любой, кто знает домен, слал бы поддельные «contact» и заходил под
чужим номером без пароля и кода.

## Шаг 8. Администратор

На чистой базе администратора нет, в панель войти нечем:

```bash
cd /opt/movex/backend
venv/bin/python scripts/create_admin.py
```

Спросит телефон, имя и пароль. Логин в панели — номер ровно как в базе,
без плюса: `998901234567`.

Панель открывается на **https://movex.004.uz/panel/**

## Шаг 9. Приложение — пересобирать НЕ нужно

В готовом `app-release.aab` уже зашит `https://movex.004.uz`, а домен мы
оставляем тот же. Значит пакет для Плей Маркета можно отдавать разработчику
как есть.

Проверить, какой адрес внутри сборки:

```bash
unzip -p app-release.aab base/lib/arm64-v8a/libapp.so | strings | grep -o 'https://[a-z0-9.-]*'
```

Пересборка понадобится только при переезде на новый домен:

```bash
cd mobile
flutter build appbundle --release --dart-define=API_BASE_URL=https://новый.домен
```
