# Выкат MoveX GO на новый сервер

Всё, что нужно для переезда на купленный VPS. Порядок важен: домен
прописывается первым, потому что без него не выпустить сертификат, а без
сертификата не включить вебхук Telegram.

## Шаг 1. Домен

**Развёрнуто 4 сентября 2026: `movexgo.uz` работает на этом сервере.**

Домен зарегистрирован не в Eskiz. Записи правятся в панели того
провайдера, чьи NS указаны в делегации — сейчас это A-Host
(`rdns1.ahost.uz`, `rdns2`, `rdns3`).

| Имя | Тип | Значение |
|---|---|---|
| `@` | A | `189.74.98.45` |
| `www` | CNAME | `movexgo.uz` |

**Правьте зону там, куда домен делегирован.** Здесь на этом потеряли
время: запись меняли в панели A-Host, пока делегация ещё указывала на
Vultr. Панель честно сохраняла — и ничего не менялось, потому что мир
читал зону Vultr. Проверять надо не панель, а делегацию:

```bash
dig NS movexgo.uz +short          # чьи NS — в той панели и правим
dig +short movexgo.uz             # должно быть 189.74.98.45
```

Существующую A-запись **править, а не добавлять вторую**: две записи на
одно имя дают случайный выбор, и часть людей уедет на старый сервер.

Чужие кэши держат старый ответ до истечения TTL — публичные резолверы
какое-то время отдают то новый адрес, то старый. Это проходит само.

## Шаг 3. Код на сервер

Каталоги `backend/` и `admin/` должны лежать **рядом**: `admin/config.php`
читает доступ к базе из `../backend/.env`. Разложить их порознь — значит
уронить админку.

### Ключ развёртывания (репозиторий приватный)

Пароль от GitHub на сервер класть не нужно и нельзя. Заводится отдельный
ключ, который умеет только читать этот один репозиторий:

```bash
ssh root@189.74.98.45
ssh-keygen -t ed25519 -C "movex-vps" -f /root/.ssh/movex_deploy -N ""
cat /root/.ssh/movex_deploy.pub
```

Показанную строку добавить на GitHub: **Settings → Deploy keys → Add deploy
key**, галочку «Allow write access» НЕ ставить — серверу писать незачем, а
украденный ключ с записью означал бы подмену кода.

Дальше сказать ssh использовать этот ключ:

```bash
cat >> /root/.ssh/config <<'EOF'
Host github.com
    IdentityFile /root/.ssh/movex_deploy
    IdentitiesOnly yes
EOF
chmod 600 /root/.ssh/config
ssh -T git@github.com        # должно поздороваться по имени репозитория
```

### Клонирование

```bash
git clone git@github.com:ВЛАДЕЛЕЦ/РЕПОЗИТОРИЙ.git /opt/movex
```

После этого обновления делаются одной командой — `deploy/update.sh` сам
делает `git pull`, дамп базы, миграции и перезапуск.

**Без GitHub** (если репозиторий останется локальным) — с этой машины:

```bash
rsync -az --exclude venv --exclude .env --exclude media --exclude .git \
      ~/Desktop/outsource/movex/ root@189.74.98.45:/opt/movex/
```

`.env`, `venv/` и `media/` не копируются: первый создаётся на сервере со
своими ключами, второй собирается под тамошний Python, третий — данные.

## Шаг 4. Настройка сервера — одна команда

```bash
DOMAIN=movexgo.uz bash /opt/movex/deploy/bootstrap_ubuntu24.sh
```

Админка по умолчанию встаёт на `/panel/`. Если у регистратора всё-таки
можно завести `admin.movexgo.uz` и так удобнее — `ADMIN_MODE=subdomain`,
но тогда нужна и вторая A-запись.

Ставит и связывает: пакеты, подкачку, пользователя `movex`, PostgreSQL с
базой и паролем, `.env` со сгенерированными ключами, venv, схему базы,
systemd-службу, nginx для API и админки, php-fpm, файрвол, ночные дампы.

Скрипт идемпотентный: повторный запуск ничего не ломает и **не
перезаписывает `.env`**.

> Старые `backend/scripts/quick_deploy.sh` и `deploy_movex_004_uz.sh` не
> использовать. Они ставят `python3.11` и Apache, а в Ubuntu 24.04 пакета
> `python3.11` нет вообще — падают на первом `apt install`. Админку они
> не поднимают совсем.

## Шаг 5. Сертификаты

Только когда `dig` из шага 1 отдаёт правильный адрес:

```bash
DOMAIN=movexgo.uz EMAIL=вы@почта bash /opt/movex/deploy/enable_tls.sh
```

Скрипт сам сверяет, куда указывает домен, и не пойдёт в Let's Encrypt
раньше времени: после пяти неудачных попыток подряд домен блокируется
на час.

## Шаг 6. Ключи в `.env`

`/opt/movex/backend/.env`, после правки `systemctl restart movex-api`.

```bash
TELEGRAM_BOT_TOKEN=          # токен бота
TELEGRAM_BOT_USERNAME=       # логин бота без @
ESKIZ_EMAIL=                 # SMS — запасной путь, если Telegram не дошёл
ESKIZ_PASSWORD=
```

`DATABASE_URL`, `SECRET_KEY` и `TELEGRAM_WEBHOOK_SECRET` скрипт уже
сгенерировал — их не трогать.

Click, Payme и FCM остаются пустыми: боевых ключей пока нет
(`docs/backend/PAYMENTS.md`, `docs/backend/NOTIFICATIONS.md`). Приложение
с пустыми ключами работает, просто эти способы оплаты и push молчат.

## Шаг 7. Вебхук Telegram

```bash
cd /opt/movex/backend
venv/bin/python scripts/telegram_webhook.py set https://movexgo.uz
venv/bin/python scripts/telegram_webhook.py info     # проверить
```

**Почему в проде именно вебхук.** Опрос (`TELEGRAM_POLLING=true`)
запускается в каждом процессе uvicorn, а их два. Два опроса одного бота
Telegram встречает ответом 409, и вход в приложение начинает работать
через раз. Вебхук от числа процессов не зависит: сообщение приходит
одно, обрабатывает его тот процесс, которому оно досталось.

Адрес закрыт секретным словом из `.env`. Пустое слово — адрес отдаёт 404:
иначе любой, кто знает домен, слал бы поддельные «contact» и заходил под
чужим номером без пароля и кода.

## Шаг 8. Администратор

На чистой базе администратора нет, в панель войти нечем:

```bash
cd /opt/movex/backend
venv/bin/python scripts/create_admin.py
```

Спросит телефон, имя и пароль. Логин в панели — номер ровно как в базе,
без плюса: `998901234567`.

Панель открывается на **https://movexgo.uz/panel/**

## Шаг 9. Приложение

APK собран под этот домен:

```bash
cd mobile
flutter build apk --release --dart-define=API_BASE_URL=https://movexgo.uz
```

Адрес зашивается при сборке и потом не меняется. Проверить, что внутри:

```bash
unzip -p app-release.apk lib/arm64-v8a/libapp.so | strings | grep -o 'https://[a-z0-9.-]*'
```

Опубликованный в Плей Маркете `.aab` собран со старым `movexgo.uz` —
его надо пересобрать под `movexgo.uz` до отправки в стор.
